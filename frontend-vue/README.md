# frontend-vue — концепция «Диспетчерская» (Vue 3 + TypeScript)

**Единственный UI приложения** (с версии 2.60.0 — vanilla-фронтенд `frontend/` и раздача на
`/legacy` удалены, см. корневой README, раздел «Изменения»; до этого — основной UI с 2.45.0,
поверх существующего FastAPI-бэкенда). Это концепция **Б, «Диспетчерская»**: тёмная NOC-консоль
дежурного инженера с несколькими выбираемыми цветовыми схемами.

## Раздача бэкендом

`GET /` отдаёт собранный `dist/` этого фронтенда (`backend/app/config.py:FRONTEND_DIR`,
по умолчанию `frontend-vue/dist`) — каталог нужно собрать (`npm run build`)
до первого запуска бэкенда, иначе `/` ответит понятной 500-ошибкой с
указанием отсутствующего файла. Клиентский роутинг
(`vue-router`, режим `createWebHistory()`) поддержан на бэкенде SPA-фоллбэком:
любой не-API GET-путь (`/vms`, `/devices` и т.п.) тоже отдаёт `index.html` —
см. `backend/app/main.py:spa_fallback`.

## Статус

Полностью реализован и подключён к реальному API один экран —
**«Инвентаризация физических устройств»** (`/devices`), включая:

- поиск (имя / серийный номер / IP управления);
- фильтры по зданию, типу устройства, признаку SIEM;
- фильтр по структурным единицам с деревом (выбор родителя включает всех
  потомков — тот же принцип parent→child expansion, что в
  `backend/app/reporting.py`);
- резолв FK id → отображаемое имя через общий стор справочников;
- пагинация на клиенте (бэкенд `/api/v1/devices` отдаёт все записи разом —
  тот же подход, что и в текущем vanilla-фронтенде, см. `CACHEABLE_LIST_RESOURCES`
  в `frontend/static/core.js`);
- **CRUD**: добавление, редактирование и удаление устройства через модальную
  форму (`DeviceFormModal.vue`) с объединённым полем «Тип / производитель /
  модель» (один select с опциями типов без модели и моделей, сгруппированных
  по производителю — выбор модели сам подставляет тип/производителя) и
  каскадными списками здание → помещение → стойка, у каждого из трёх —
  кнопка быстрого добавления, и обработкой
  структурированных 409-конфликтов бэкенда (`DUPLICATE_SYSTEM_NAME`,
  `RACK_POSITION_OCCUPIED`, `REFERENCED_BY_OTHER_RECORDS`) — тот же
  retry-with-confirm UX, что в `frontend/static/app.js:saveForm`, включая
  `window.confirm()` вместо кастомного диалога, для консистентности с
  остальным приложением. Форма также редактирует открытые порты,
  программные активы, физические интерфейсы и VLAN устройства
  (`OpenPortListEditor.vue`/`SoftwareAssetListEditor.vue` — те же
  компоненты, что у ВМ; `DeviceInterfacesEditor.vue` — компактная таблица
  портов (VLAN на порту/IP-адреса/описание — под разворачиваемой строкой) с
  генерацией по шаблону и вложенными IP, persist через атомарный
  `PUT /devices/{id}/interfaces`; подинтерфейсы порта (отдельный VLAN, свои IP и открытые порты)
  редактирует `InterfaceSubinterfacesEditor.vue` в раскрытых деталях порта, правила и payload —
  в `utils/subinterfaces.ts` (там же пересчёт автоимён при переименовании порта и проверка «VLAN подинтерфейса ещё
  назначен устройству», уведомление о снятом VLAN выдаёт `DeviceFormModal.vue`; кнопка «Показать» в нём вызывает
  `revealStaleSubinterfaces()` редактора портов, а перенос подинтерфейса на другой VLAN использует справочник VLAN
  `vlanCatalog`, чтобы знать номер уже недоступного VLAN; массовый перенос — `moveStaleSubinterfaces`, одно правило смены
  VLAN с пересчётом автоимени — `reassignSubinterfaceVlan`), список грузится из
  `GET /devices/{id}/subinterfaces`; `DeviceVlanListEditor.vue` — назначение
  VLAN устройству, доступные VLAN ограничены членством в VLAN-домене, persist
  через атомарный `PUT /devices/{id}/vlans` по diff'у, ещё не сохранённое
  включение в домен можно отменить крестиком на чипе) —
  подробности и явные ограничения см. «Ещё не сделано»;
- toast-уведомления об успехе/предупреждении/ошибке (`useToast`/`ToastHost.vue`;
  warning скрывается через 10с, error — только вручную) — аналог
  `notify()`/`notifyError()` из vanilla-фронтенда.

Дашборд (`/dashboard`) подключён к `/api/v1/dashboard` и показывает реальные
счётчики.

Второй полностью рабочий экран — **«Информационные системы»** (`/information-systems`,
Лист 1): список с поиском/фильтром SIEM, CRUD через модалку. Форма покрывает
собственные поля `InformationSystem`, а также вложенные связи — подразделения
(`CatalogPickerListEditor.vue`), протоколы передачи данных
(`ISProtocolsListEditor.vue` — та же логика автоподстановки протокола/порта из
справочника, что в `OpenPortListEditor.vue`), источники размещения и IP
(`ISSourcesListEditor.vue` — унифицированная замена устаревших отдельных
таблиц устройство/ВМ/контейнер/IP; выбор ВМ автоподставляет её хост, ВМ
текущего хоста строки поднимаются в начале списка) и места размещения
(`CatalogPickerListEditor.vue`, тот же компонент, что у подразделений — обе
связи имеют форму "выбери одну запись справочника"). Персистится через
атомарный `PUT /resources/information-systems/{id}/details` — тот же приём,
что интерфейсы устройства (см. четвёртый экран ниже), только путь под
`/resources/`, а не `/devices/`. При первом открытии формы для ИС, у которой
ещё нет записей в унифицированной таблице `sources`, но есть данные в
устаревших таблицах, они на лету собираются в `sources` — портировано
дословно с `openInformationSystemForm()`/`migrateLegacyToSources()`-логики
`frontend/static/information-systems.js`, иначе такая ИС выглядела бы в
новом UI так, будто у неё вообще нет источников.

Третий — **«Виртуальные машины»** (`/vms`, Лист 4): список, поиск, CRUD.
Форма учитывает бизнес-правила бэкенда: хост (`physical_device_id`) отфильтрован
на клиенте до устройств типа «Сервер»/«Система хранения» (сервер всё равно
отклонит остальные типы с 422 — фильтр только для UX), а `hypervisor_os_id`
не редактируется — бэкенд всегда пересчитывает его сам из ОС выбранного хоста,
форма показывает это как read-only предпросмотр. Форма также редактирует
IP-адреса ВМ (`VmIpListEditor.vue`, `/resources/ip-addresses?owner_type=virtual_machine`),
её открытые порты (`OpenPortListEditor.vue`, `/resources/open-ports?owner_type=virtual_machine`)
и развёрнутые программные активы (`SoftwareAssetListEditor.vue`,
`/resources/deployed-software?owner_type=virtual_machine`) — строки staged
локально (можно заполнить ещё до сохранения новой ВМ, когда её id ещё не
существует) и после сохранения самой ВМ уходят тремя атомарными запросами
`PUT /vms/{id}/ip-addresses | open-ports | deployed-software`
(`src/api/vmNestedLists.ts`): сервер сравнивает список с БД по id — записи с id
обновляются на месте, без id создаются, убранные в форме удаляются. Это
заменило схему delete-затем-recreate из vanilla-версии
(`saveVMIPs()`/`saveVMOpenPorts()`/`saveVMSoftware()` в
`frontend/static/vm-editors.js`). `OpenPortListEditor.vue` и
`SoftwareAssetListEditor.vue` не завязаны на владельца (принимают готовые
строки и справочник через props) — переиспользованы без изменений на экране
устройств ниже.

Четвёртый — **«Подключения»** (`/connections`, Лист 3), самый структурно
сложный: каскадный выбор устройство→порт для источника и назначения, список
портов на каждом шаге исключает уже занятые активным подключением (сервер
всё равно отклонит конфликт 409 — фильтр только для UX). Использует общий
`/resources/connections`, где `enrich_connections()` уже возвращает резолвленные
имена устройств/портов/типа линии — без клиентских джойнов для отображения таблицы.
Порты устройства можно редактировать прямо с этого экрана — не заходя в форму
устройства: кнопка «Управлять портами» рядом с каждым select порта в форме
подключения (`ConnectionFormModal.vue`) и такая же кнопка у каждого порта прямо
в строке таблицы (`ConnectionsView.vue`) открывают `DevicePortsModal.vue` —
переиспользует `DeviceInterfacesEditor.vue` и общий модуль
`api/deviceInterfaces.ts` (тот же, которым пользуется `DeviceFormModal.vue`,
без дублирования логики load/persist). После сохранения список интерфейсов в
`catalogs.items['interfaces']` обновляется точечно (`catalogs.replaceDeviceInterfaces`),
без полной перезагрузки справочников; если отредактированный порт был удалён,
его выбор в форме подключения сбрасывается автоматически.

Подключение порта можно создать и прямо в форме устройства — в блоке «Порты /
интерфейсы» у раскрытой строки порта (`InterfaceConnectionEditor.vue`, чистые
функции — `utils/interfaceConnections.ts`). У нового порта ещё нет id, поэтому
подключение уходит на сервер не отдельным запросом, а в ключе `connection`
элемента `interfaces` того же `PUT /devices/{id}/interfaces`
(`api/deviceInterfaces.ts:persistDeviceInterfaces`): нет ключа — подключение не
менялось, `null` — отключить, объект — создать/обновить. Отправляются только
изменённые подключения (снимок на момент открытия формы); редактор включается
пропсом `editConnections` — `DevicePortsModal.vue` его не включает и работает
как раньше.

Сосед может быть и портом **этого же устройства** (в том числе ещё не сохранённого):
строки формы ссылаются друг на друга стабильным ключом `InterfaceDraftRow.key`, а
на сервер такая связь уходит номером строки соседа — `connection.peer_row` (ключ
`key` на сервер не отправляется). Порты, которые эта форма сама освобождает
(«Отключить» или переназначение), сразу доступны другим строкам: за один запрос
можно обменять соседей (A: P→Q, B: Q→P) — сервер строит план подключений целиком
и считает прежние порты переставляемых подключений свободными. При удалении строки
ссылки на неё в других строках очищаются, а оставшийся «висячий» сосед блокирует
сохранение с понятным текстом.

Порты и устройства-соседи, подключения редактируемого устройства и расхождения
конфигурации с соседними портами форма берёт **с сервера**, а не из общих списков
с потолком в 1000 записей и не из полного `GET /devices` (`api/deviceConnectivity.ts`).
Устройства-соседей ищет `GET /devices/options` (поиск `q`, страницы по 50,
`include` — текущий сосед, `exclude` — редактируемое устройство; в `SearchableSelect.vue`
для этого режим `remote`), расхождения считает `utils/portConflicts.ts` по соседям из
`interface-connections` и перечитывает их после «Применить конфигурацию соседу»
(событие `neighbors-changed`). Порты соседа отдаёт
`GET /devices/{id}/free-interfaces` (свободные порты, пагинация `offset`/`limit ≤ 500`,
поиск `q`, повторяемый `include` — вернуть занятыми текущего соседа и освобождаемые
формой порты), подключения устройства — `GET /devices/{id}/interface-connections`.
Ответы устаревших запросов при быстрой смене устройства отбрасываются. Форма устройства при сбое
после создания (например, не сохранились порты) не создаёт дубль: повторное
«Сохранить» обновляет уже созданное устройство и не дублирует связи с доменами.

Пятый — **«Отчёты»** (`/reports`): генерация регламентного Excel-отчёта
(4 листа) с опциональными фильтрами (по одной ИС, по структурным единицам —
переиспользует `StructuralUnitTree.vue` из фильтра устройств) и выгрузки
журнала аудита за период. Файл скачивается без ухода со страницы SPA
(`<a download>`, программный клик). Рядом — экран **«Шаблоны отчётов»**
(`/report-templates`, `ReportTemplatesView.vue`, ссылка с этого же экрана):
жизненный цикл шаблонов конструктора произвольных отчётов — список,
создание, переименование, дублирование, удаление, генерация, история
версий с восстановлением. Визуальный редактор содержимого — **«Конструктор»**
— доступен для обоих форматов: xlsx открывает `ReportGridEditorView.vue`
(`/report-templates/{id}/editor` — листы, колонки, строки с привязкой к
данным, ячейки с выделением/объединением и 4 типами содержимого), docx —
`ReportDocxEditorView.vue` (`/report-templates/{id}/editor-docx` — блоки
заголовок/абзац/таблица/разрыв страницы, добавление/удаление/перемещение,
блок-таблица переиспользует ту же логику источника данных, что и
повторяющаяся строка xlsx). Оба редактора и общая логика между ними
подробно описаны в «Ещё не сделано» ниже.

Шестой — **«Журнал аудита»** (`/audit-log`): только чтение (аудиторский след
намеренно не редактируется через UI), поиск, фильтр по действию и по разделу.
Имя раздела резолвится не хардкодом, а через `GET /api/v1/resources` (то же,
что `DISPLAY_NAMES` на бэкенде) — не расходится при добавлении новых ресурсов.

Седьмой — **«VLAN»** (`/vlans`): группировка по VLAN ID через специализированный
`/api/v1/vlan-dashboard` (один и тот же ID может иметь разные определения в
разных доменах — например, «локальный» VLAN без домена; экран это явно
отмечает как «требует внимания», а не считает ошибкой). CRUD отдельных
определений через общий `/resources/vlans`. Массовое назначение одного VLAN
нескольким устройствам сразу (`VLANFormModal.vue`-соседняя панель,
`POST /device-vlans/bulk-assign`) и полное управление VLAN-доменами
(`VLANDomainsPanel.vue`/`VLANDomainFormModal.vue` — CRUD, состав участников,
кнопка синхронизации от устройства-источника) раскрываются отдельными
кнопками рядом с фильтром.

Восьмой — **«Здания и помещения»** (`/buildings`): трёхуровневая иерархия
Здание → Помещение → Стойка с раскрывающимися узлами и CRUD на каждом уровне.

Девятый — **«Структурные подразделения»** (`/structural-units`): дерево с
CRUD (добавить корневую/дочернюю единицу, редактировать, удалить). Удаление
единицы с живыми потомками блокируется на клиенте до похода на сервер
(понятное сообщение вместо непрозрачного 409), сервер всё равно проверяет
это самостоятельно — двойная защита.

**Все разделы меню теперь имеют рабочие экраны в новом UI**, включая оба
редактора конструктора отчётов (xlsx и docx) и предпросмотр содержимого в
обоих — конструктор отчётов полностью перенесён.

## Стек

Vue 3 (`<script setup>` + TypeScript) · Pinia · vue-router · Vite · Vitest +
`@vue/test-utils`.

## Разработка

```bash
npm install
npm run dev        # Vite dev-сервер на :5173, проксирует /api на 127.0.0.1:8000
npm run build       # vue-tsc (проверка типов) + сборка в dist/
npm test            # vitest run
npm run e2e         # сборка + проверки интерфейса в настоящем браузере (Playwright, Chromium) — см. «E2E-проверки»
npm run lint        # ESLint (eslint.config.js): v-html без санитизации, any, console.log, new Date(строка) и др.
npm run lint:fix    # ESLint с автоисправлением там, где оно безопасно
npm run format      # Prettier (.prettierrc) — переформатирует файлы; format:check только проверяет
npm run format:check
```

### Линтер и форматирование

`npm run lint` и `npm run format:check` должны проходить без замечаний; оба запускаются в CI (job `test`) до сборки и тестов.
Перед коммитом достаточно `npm run lint:fix && npm run format`.

- **Стиль Prettier** (`.prettierrc`): без точек с запятой, одинарные кавычки, запятая в конце многострочных конструкций, ширина строки 160.
  Ширина 160, а не стандартные 100 из шаблона create-vue, выбрана потому, что в коде много длинных атрибутов шаблонов Vue и строк
  с русским текстом: при 100 разбиение затронуло бы в четыре раза больше строк и ухудшило чтение разметки. Менять `htmlWhitespaceSensitivity`
  (по умолчанию `css`) не нужно: в этом режиме Prettier не меняет значимые пробелы между строчными элементами.
- **`v-html`** запрещён правилом `vue/no-v-html`. Допустимо только для разметки, прошедшей `sanitizeSvg()`, и каждое такое место помечается
  комментарием с причиной прямо перед строкой: `<!-- eslint-disable-next-line vue/no-v-html -- разметка прошла sanitizeSvg -->`.
  Комментарий без причины после `--` не принимается в ревью.
- **Намеренно неиспользуемое** (параметр, переменная, деструктурируемое поле) называется с подчёркивания: `_url`, `_event`.
- **`git blame`.** Коммит с массовым форматированием перечислен в `.git-blame-ignore-revs` в корне репозитория; GitHub учитывает файл
  автоматически, локально включите один раз: `git config blame.ignoreRevsFile .git-blame-ignore-revs`. После нового массового форматирования
  добавляйте хэш его отдельного коммита в этот файл и не переписывайте историю после этого — хэш должен остаться верным.
- **Шаблон с `<` и `>` в тексте.** Строки вида «<порт>.<VLAN>» не пишите внутри `{{ }}` в шаблоне: Vue разбирает их верно, а Prettier принимает
  за теги и падает с `SyntaxError`. Вынесите строку в `computed` или константу (пример — `hint` в `InterfaceSubinterfacesEditor.vue`).

Бэкенд должен быть поднят отдельно на `127.0.0.1:8000` (см. корневой README) —
`vite.config.ts` содержит прокси `/api -> http://127.0.0.1:8000`, тот же
same-origin принцип, что и в проде, где собранный `dist/` раздаётся самим
FastAPI (см. `backend/app/api/system.py`, `backend/app/main.py`, `FRONTEND_DIR`).

### Аудит зависимостей

`npm ci` (в том числе из `installer/build_windows.bat`) должен заканчиваться строкой `found 0 vulnerabilities`; CI блокирует слияние только по
runtime-зависимостям (`npm run audit:gate` — `npm audit --omit=dev --audit-level=high` с исключениями, см. ниже), но полный `npm audit` держим
чистым, когда это возможно, чтобы при сборке EXE не было шума.

**Исключения гейта** (`ALLOWLIST` в `scripts/audit-gate.mjs`). У `npm audit` нет списка исключений, а для свежей уязвимости исправленной версии
может ещё не быть: тогда шаг CI красный для всех, и `overrides` не помогают (ставят ту же уязвимую версию). Исключение — это id advisory, причина
и срок (`expires`); после срока оно перестаёт действовать, и гейт падает снова. Исключение действует только на указанный advisory — любая другая
уязвимость high и выше по-прежнему валит шаг; ошибка самого `npm audit` (нет сети) — тоже падение. Сейчас одно исключение — `picomatch`
(GHSA-fc5q-39xc-vjpf, ReDoS, исправления в npm нет): библиотека приходит через `vue-router`/`vite` и работает только при сборке, в `dist/` её
нет. Снять исключение: когда `npm view picomatch version` выше 4.0.7 — обновить lock (`npm update picomatch`), удалить запись из `ALLOWLIST`
(скрипт сам подскажет «исключение больше не нужно», когда advisory пропадёт из отчёта). Проверка гейта: `npm run audit:gate`.
Блок `overrides` в `package.json` (`minimatch` `^11.0.8`, `glob` `^14.0.6`) закрывает замечания к dev-инструментам, пока `typescript-eslint`
и `@vue/test-utils` (через `js-beautify`) сами не перешли на исправленные версии; подробности и условие снятия — в корневом
[`README.md`](../README.md), раздел «Зависимости backend» → «Цепочка поставок». Не используйте `npm audit fix --force`: он понижает
`typescript-eslint`, `eslint-plugin-vue` и `@vue/test-utils`. После правки `package.json` пересобирайте lock командой `npm install`, а проверяйте `npm ci`.

### E2E-проверки интерфейса (Playwright)

Юнит-тесты (vitest + jsdom) раскладку не считают — `css: false`, а у jsdom нет движка вёрстки, — поэтому обрезанное мобильное меню,
пустые иконки спрайта или внешние запросы за шрифтами они не видят. Эти дефекты ловят проверки в `e2e/`: настоящий Chromium идёт по
собранному приложению. Появились после ревью «merge/review-2158-executors — веб-интерфейс» (рекомендация 3).

```bash
npx playwright install chromium     # один раз: браузер для Playwright (в CI ставится шагом job `e2e`)
npm run e2e                         # vite build + все проверки (~2 мин на 2 ядрах)
npx playwright test e2e/shell.spec.ts --grep UI-1    # одна проверка; --headed и --ui — для отладки
npx playwright show-report          # HTML-отчёт после прогона (в CI — артефакт при падении)
```

- **Как это запускается.** `playwright.config.ts` через `e2e/start-backend.mjs` поднимает backend на чистой временной SQLite
  (`alembic upgrade head`, затем uvicorn на `127.0.0.1:8765`) и раздаёт им собранный `dist/` — с боевым CSP, поэтому, например,
  запрос к стороннему CDN за шрифтами или блокировка локального шрифта видны как ошибки. Рабочая база и каталог отчётов не
  затрагиваются. Нужен интерпретатор Python с зависимостями backend: по умолчанию `python3` из PATH, иначе `E2E_PYTHON=/путь/к/venv/bin/python`.
- **Переменные окружения.** `E2E_PYTHON` — интерпретатор backend; `E2E_CHROMIUM_PATH` — свой Chromium вместо скачанного Playwright (закрытый
  контур, образ без доступа к CDN); `E2E_PORT` — порт (8765); `E2E_REUSE_SERVER=1` — не поднимать backend, а взять уже запущенный на
  этом порту (для отладки; проверки ожидают пустую базу); `E2E_SERVER_LOGS=1` — показывать журнал uvicorn.
- **`e2e/shell.spec.ts`** — каркас: мобильное меню (390×667) прокручивается, каждый пункт достижим, закрытое меню вне порядка фокуса,
  Esc закрывает меню и меню пользователя; сайдбар и топбар закреплены при прокрутке (1440×900); иконки меню все нарисованы и не
  повторяются; `color-scheme: dark`; геометрия `.status-dot`; шрифты приходят с того же origin, без внешних запросов и ошибок CSP.
  Каждая проверка названа номером находки из ревью (UI-1…UI-11); дальше — обновление страницы и закладки при включённой
  аутентификации и значок вкладки (`/favicon.ico`).
- **`e2e/routes.spec.ts`** — обход всех 17 экранов без параметров на трёх размерах окна (390, 820, 1440): страница не шире окна,
  нет ошибок в консоли, неудачных и внешних запросов, пустых иконок. База чистая, поэтому видны только пустые состояния; вёрстку
  таблиц с данными нужно проверять отдельно, на заполненной базе.
- **`e2e/shell-mobile.spec.ts`** — каркас на телефоне: шапка с длинным заголовком не выше 80 px, высота шапки совпадает с `--topbar-h`,
  страница диаграммы не прокручивается, холст не короче 320 px, название в меню не рвётся (UI-05, UI-15).
- **`e2e/filled-data.spec.ts`** и **`e2e/diagram-filled.spec.ts`** — экраны и диаграмма на ЗАПОЛНЕННЫХ данных (чистая база показывает только
  пустые состояния): плейсхолдеры поиска не обрезаны, у страниц нет горизонтальной прокрутки, узлы лежат внутри холста, кнопки масштаба и
  мини-карта работают, параллельные связи сворачиваются в «×3» без пересекающихся подписей. Данные создаются фикстурами и убираются
  после каждого теста.
- **`e2e/modals.spec.ts`** — модальные окна: Esc закрывает только верхнее из вложенных окон (и сначала открытый список выбора), у диалога есть
  доступное имя, настоящие Tab / Shift+Tab не выпускают фокус из окна, при закрытии фокус возвращается на кнопку, открывшую окно,
  вложенное окно лежит выше нижнего, страница под окном не прокручивается.
- **`e2e/a11y-contrast.spec.ts`** — контраст текста не ниже WCAG AA (движок axe-core) на каждом экране в каждой цветовой схеме, и живые
  области уведомлений: обе есть в DOM до первого уведомления, ошибка действия появляется внутри `role="alert"`.
- **`e2e/table-scroll-hint.spec.ts`** — подсказка горизонтальной прокрутки таблиц (F-05): на телефоне затухает правый край, контейнер в
  порядке фокуса; подсказка совпадает с фактом переполнения.
- **`e2e/diagram-edges.spec.ts`** — рёбра диаграммы (F-07): на схеме из 18 узлов не проходят сквозь узлы и не накладываются друг на друга,
  а после перетаскивания узла маршруты пересчитываются.
- **`e2e/connection-resolution.spec.ts`** — панель «Расхождение конфигурации портов» (FE-08): после «Сохранить» фокус переходит в панель,
  а «Вернуться к правке» возвращает его на «Сохранить».
- **Аутентификация** в проверках подменяется в браузере (`signInAsAdmin` в `e2e/fixtures.ts`: ответы `/auth/status` и `/auth/me` +
  токен в localStorage), а не включается на сервере: общая база между параллельными тестами от этого сломалась бы.
- **Известные дефекты** оформляются как `test.fail()`: когда дефект исправят, тест «неожиданно пройдёт» — и Playwright потребует
  убрать пометку. Сейчас таких нет: потеря экрана при обновлении страницы с включённой аутентификацией исправлена, её проверяет
  блок «глубокие ссылки при включённой аутентификации» в `e2e/shell.spec.ts`.
- **Не входит в vitest.** `e2e/**` исключён из `vitest.config.ts`; типы проверяет `vue-tsc -b` (`tsconfig.e2e.json`), стиль — ESLint и
  Prettier, как для остального кода.

## Цветовые схемы

Три схемы: **Бирюза** (по умолчанию), **Индиго**, **Медь** — см.
`src/stores/theme.ts` и `src/styles/theme.css`. Меняется только фирменный
акцент (`--brand`/`--brand-soft`) и лёгкий оттенок фона; статусные цвета
(норма/внимание/тревога) зафиксированы во всех схемах, чтобы выбор акцента не
мог сделать предупреждение неотличимым от активного пункта меню. Выбор
сохраняется в `localStorage` (`itr.colorScheme`).

## Архитектурные решения, важные для продолжения работы

- **Формы ответов API.** `/api/v1/resources/{resource}` всегда отдаёт
  `{items, total, offset, limit}` (см. `backend/app/services/crud/generic.py:list_resource`),
  а специализированный `/api/v1/devices` — `{items, total}` без `offset/limit`
  (без серверной пагинации). Это разные формы — см. `PagedResponse<T>` vs
  `DevicesResponse` в `src/api/client.ts` / `src/api/types/devices.ts` (типы разбиты по доменам в `src/api/types/`, публичные
  импорты идут через `types/index.ts`).
- **serialize() не резолвит внешние ключи** — отдаёт сырые id колонок.
  Резолв в отображаемое имя — на фронтенде, через `useCatalogsStore().label()`.
  Исключение: `enrich_connections()` (и `enrich_devices()`) резолвят некоторые
  поля сами на бэкенде — см. `Connection`/`Device` типы, где часть полей уже
  готовые строки, а не id.
- **Ключ ресурса в `/resources/{key}` не всегда очевиден из имени модели** —
  например, `DeviceInterface` живёт под ключом `interfaces`, а не
  `device-interfaces` (наступили на это при разработке `ConnectionFormModal`:
  404 на ровном месте). Источник истины — `backend/app/registry.py`, а не
  интуиция по названию SQLAlchemy-модели.
- **Структурные единицы** — самоссылающаяся иерархия `parent_id` (тот же
  паттерн, что `Department`). Фильтр по единице должен разворачиваться на всех
  потомков, а не быть точным совпадением id — см.
  `catalogs.unitAndDescendantIds()` и покрывающий тест в
  `src/stores/__tests__/catalogs.spec.ts`.
- Тесты стора используют фикстуры (`src/stores/__tests__/fixtures.ts`),
  снятые по форме с реальных ответов локально поднятого бэкенда, а не
  придуманы вручную.
- **"Устройство-хост" (сервер/СХД) определяется по названию типа устройства**,
  не по отдельному флагу на `PhysicalDevice` (такого поля нет в модели) —
  вынесено в `src/utils/deviceFilters.ts:filterHostDevices()`, используется и
  в форме ВМ (выбор хоста), и в форме ИС (`ISSourcesListEditor.vue`, тип
  источника «Физический сервер»). Совпадает с фильтром на бэкенде
  (`validate_vm_host` в `backend/app/services/validation.py`) — если меняется
  список ключевых слов там, стоит проверить и здесь.
- **Атомарные вложенные ресурсы поверх `/resources/`.** Не всё сохраняется
  через generic create/update/delete у ресурса — интерфейсы устройства
  (`PUT /api/v1/devices/{id}/interfaces`) и детали ИС
  (`PUT /api/v1/resources/information-systems/{id}/details`) представляют собой
  атомарные "пересобери всё целиком" эндпоинты: одним запросом
  создают/обновляют/удаляют набор дочерних записей по diff'у с тем, что уже
  в БД (см. `sync_interfaces` в `backend/app/services/crud/interfaces.py` и
  `sync_information_system_details` в `backend/app/services/crud/information_system.py`). Оба используют `api.put()` напрямую
  (`src/api/client.ts`), а не `createResource`/`updateResource`/`deleteResource`.
  Загрузка/валидация/сохранение интерфейсов вынесены в `api/deviceInterfaces.ts`
  (не дублируются между `DeviceFormModal.vue` и `DevicePortsModal.vue`) —
  если понадобится третья точка входа для управления портами, использовать
  этот модуль, а не копировать логику снова.

- **Токен сессии лежит в `localStorage` (`itr:auth-token`) — принятый риск** (ревью B-05). Скрипт страницы может прочитать токен, поэтому
  XSS даёт его кражу. Риск принят осознанно и смягчён тремя вещами: (1) CSP бэкенда (`default-src 'self'`, `object-src 'none'`,
  `frame-ancestors 'none'`; `backend/app/config.py:CSP_POLICY`, заголовки — `backend/app/services/auth/security_headers.py`) не пускает
  чужие и встроенные скрипты; (2) пользовательский HTML попадает в страницу одним путём — SVG-иконки устройств через `v-html` после
  очистки DOMPurify (`utils/sanitizeSvg.ts`, один проход, без повторного разбора — B-04); (3) от кросс-сайтовых запросов бэкенд
  защищён сам. Обоснование держится на двух допущениях — «`v-html` только у SVG-иконок» и «токеном занимается один модуль,
  `api/client.ts`»: их проверяет `src/__tests__/securityPolicy.spec.ts`, и если он падает, нужно пересматривать риск, а не править тест.
  Токен первичной настройки (`itr:setup-token`) — в `sessionStorage` и гаснет вместе с вкладкой.
  **Что CSP не закрывает — `style-src 'self' 'unsafe-inline'`**. Для скриптов `unsafe-inline` и `unsafe-eval`
  НЕ разрешены (скрипты берутся из `default-src 'self'`), а встроенные стили разрешены. Остаточный риск — подмена внешнего вида и
  вытягивание данных через CSS-селекторы при внедрении разметки; выполнить свой скрипт и прочитать токен это не позволяет. Почему
  разрешение осталось, проверено только частично: в исходниках 17 привязок `:style` и ни одного статического `style="…"`, а Vue
  выставляет такие стили через CSSOM, который строгая политика не блокирует, — то есть убрать `'unsafe-inline'`, вероятно, можно. Но
  библиотеки (`@vue-flow/core`) и атрибуты `style` в очищенных SVG-иконках в браузере с такой политикой не проверялись. Если решите
  ужесточить, начните с прогона Playwright-проверок (`npm run e2e`) при `INFRA_REGISTRY_CSP` без `'unsafe-inline'` в `style-src`.
  **На будущее** — перейти на cookie `HttpOnly; SameSite=Strict` (токен станет недоступен скриптам) и добавить CSRF-токен для запросов,
  меняющих данные; проверка Origin для этого уже готова: `SameOriginGuardMiddleware` в `backend/app/services/csrf_guard.py` отклоняет
  POST/PUT/PATCH/DELETE к `/api/` с чужого origin (403 `CROSS_ORIGIN_BLOCKED`) при любом режиме аутентификации, так что при переходе на cookie
  защита от CSRF остаётся на месте, а отдельный токен добавляет второй рубеж. Затрагивает `api/client.ts` (заголовок `Authorization` → `credentials: 'include'`), `stores/auth.ts`, вход/выход и
  бэкенд (выдача cookie, проверка CSRF) — делается вместе с бэкендом, отдельной задачей. Вернуться к вопросу раньше стоит, если
  появится пользовательский HTML вне SVG, ослабится CSP (`INFRA_REGISTRY_CSP`) или приложение выставят за пределы доверенной сети.
- **Модальные окна.** Все окна строятся на `components/BaseModal.vue`: подложка `.modal-overlay` (описана один раз), Teleport и слой окна.
  У окна пять сторон: стек открытых окон (кто верхнее, слой `--z-modal + номер в стеке`, признак `hasOpenModal`), закрытие по клику на
  подложку (`useOverlayDismiss.ts`), Esc, ловушка и возврат фокуса (`useFocusTrap.ts`) и блокировка прокрутки страницы. Единственная точка
  входа — `useModalLayer()` в `composables/modalLayer.ts`: она вызывает их в нужном порядке (порядок не случаен, причины — в комментарии
  файла). Свою подложку и числовой `z-index` для окна заводить не нужно (`modalDialogs.spec.ts` не даёт этого сделать). При открытом
  окне меню и основная область `inert`; владелец признака — `AppShell`. В тестах Teleport окон по умолчанию отключён
  (`src/__tests__/setup.ts`); тест, которому нужен настоящий Teleport, включает его явно.
- **Размер страницы списков.** Одна шкала на весь интерфейс — `PAGE_SIZE_OPTIONS` (10 / 25 / 50 / 100) и `DEFAULT_PAGE_SIZE` (10) в
  `utils/pageSize.ts`; у `usePagedList` нет собственного «размера по умолчанию». Все значения шкалы не больше серверного предела журнала
  аудита (200). Пустой реестр и «фильтры ничего не оставили» — разные состояния (`components/ListEmptyRow.vue`, `resetFilters()` в сторах).
- **Неполные данные не сохраняются.** Если форма сохраняет список целиком (PUT приводит список на сервере к присланному), список, который
  не загрузился или усечён (`listAllResource` читает не больше 50 000 записей), нельзя отправлять: сервер удалил бы то, чего форма не видела.
  `api/assertComplete.ts` превращает усечение в `IncompleteDataError` (`loadAllComplete` один раз перечитывает список, если запись
  удалили во время загрузки), `composables/loadNestedList.ts` — состояние загрузки вложенного списка, `components/DataLoadNotice.vue` —
  сообщение «загружено n из N» с кнопкой «Повторить загрузку».
- **Перекрывающиеся запросы: побеждает последний.** Два `reload()` подряд (после сохранения формы и по событию обновления) могли
  закончиться в обратном порядке: ответ на первый запрос приходил позже и затирал свежий список, а `loading` сбрасывался по окончании
  первого. Вся загрузка списка идёт через `utils/latestRequest.ts`: `latest.run(this, { fetch, apply, errorMessage })` ведёт `loading` и
  `error` стора и отбрасывает ответ, ошибку и `finally` запроса, который успел вытеснить более поздний. Так загружают данные все сторы
  (`catalogs`, `connections`, `containers`, `deviceStacks`, `devices`, `informationSystems`, `reportTemplates`, `vlanDomains`, `vlans`,
  `vms`, `auditLog`, `connectionsDashboard`, `portSyncRules`, `auditSettings`) и `diagram.load(id)` (быстрое переключение схем показывало
  не ту схему; сохранение отложенной раскладки до замены схемы — параметр `prepare`). Новый стор с асинхронной загрузкой заводит свой
  экземпляр `createLatestRequest()` на уровне модуля и загружает только через `run()`: собственных `begin()` / `isLatest()` в сторах нет.
  Есть и обратное направление той же гонки. Когда стор сам применяет подтверждённое сервером изменение к уже показанным данным
  (`portSyncRules.upsert` / `remove` / `move`, `catalogs.addCatalogItem` / `replaceInterface` / `replaceDeviceInterfaces` / `addDiagramIcon`,
  `auditSettings.save`), перед этим вызывается `latest.invalidate(this)`: загрузка, начатая до изменения, принесла бы снимок без него и
  откатила бы изменение (выключенное правило снова включено, новая запись справочника пропала). `invalidate` сбрасывает `loading` и
  возвращает `true`, если загрузка шла, — тогда стор запускает её заново, чтобы остальные данные не остались устаревшими.
- **Скачивание файлов.** `api/saveBlob.ts` — единый «сохранить blob» (ссылка освобождается через 30 с); ошибки скачивания разбирает общий
  `apiErrorFromResponse`; имя файла берётся из `filename*` заголовка `Content-Disposition` (`filenameFromDisposition` в `api/diagrams.ts`).
