# Infra Registry — реализация предложений по улучшению (шаг 7)

## 2.5 (интерфейс). Ограничена высота длинных вложенных списков

`.nested-list` (VLAN устройства, IP-адреса ВМ, открытые порты ВМ, детали ИС) и `.interface-cards`
(Порты/интерфейсы) раньше ничем не ограничивались по высоте — при большом числе строк модальное
окно растягивалось на всю страницу, требуя прокрутки всей страницы вместо прокрутки внутри списка
(единственное исключение уже было — `.vlan-checks` с `max-height:140px`). Добавлены собственные
`max-height`/`overflow:auto` (420px и 640px соответственно, с небольшим отступом у карточек
интерфейсов под полосу прокрутки).

## 2.4 (интерфейс). Сортировка таблиц списков по клику на заголовок

Заголовки таблиц теперь кликабельны — сортируют список по этой колонке; повторный клик меняет
направление (со стрелкой ▲/▼ в заголовке активной колонки). Реализовано без похода на сервер:
`renderList` теперь только один раз загружает данные и вычисляет служебные (`lookups`) данные для
внешних ключей, а собственно построение `<thead>`/`<tbody>` вынесено в отдельную `renderTable()`,
переиспользуемую сортировкой. Сортировка: числовые колонки — по значению, остальные — через
`localeCompare` с русской локалью (корректный алфавитный порядок для кириллицы), `null`/пустые
значения всегда уходят в конец независимо от направления сортировки, колонки с внешним ключом
сортируются по отображаемому (человекочитаемому) значению, а не по внутреннему UUID.

Логика сортировки (числа/строки на русском/null-значения/переключение направления) проверена
отдельной эмуляцией в Node.js — все проверки прошли, включая контроль того, что `null` не
"телепортируется" в начало списка при смене направления сортировки.

## Проверка

- `node --check app.js` — чисто, дублирующихся функций нет, все новые идентификаторы (`list-head`,

- Отдельная эмуляция сортировки в Node.js: сортировка строк на кириллице по алфавиту, переключение
  направления по повторному клику, числовая сортировка, `null`-значения в конце при любом
