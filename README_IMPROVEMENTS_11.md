сборщика опирается на глобальную видимость функций через `onclick=""`-атрибуты по всему HTML,
и модуляризация (ES-модули по умолчанию не кладут функции в `window`) требует либо явного
экспорта каждой функции, либо полной переработки способа навешивания обработчиков — серьёзная,
рискованная переработка, а не безопасное дополнение.

## 3.5 (качество кода). Магические строки → именованные константы

На backend такие строки (коды ошибок API, типы действий аудита, допустимые значения
`source_type`) встречались **по одному разу на место использования** — реального дублирования не
было, но сами значения пересекают границу backend/frontend (frontend сверяется с этими же
строками). Добавлен `backend/app/constants.py` (`ErrorCode`, `AuditAction`, `SourceType`,
`OwnerType`) — используется в `crud.py` везде, где раньше был литерал; провал — единая точка,
где виден весь набор допустимых значений.

**На фронтенде не тронуто.** Там `'manual'`/`'device'`/`'vm'`/`'container'` действительно
повторяются (до 7 раз для одного значения) в **той же зоне IS-редактора источников**, которую в
этой сессии уже несколько раз чинили с особой осторожностью — риск ошибиться при массовой замене
в уже отлаженном месте не оправдан ради стилистического выигрыша. Оставлено как задокументированная
рекомендация на будущее, не как выполненная в этом шаге правка.

Добавлен `backend/tests/test_constants.py` — 4 теста, фиксирующие сами значения констант как
контракт (чтобы случайное переименование в будущем сразу давало красный тест).

## 1.5 (функционал, облегчённая версия). Предупреждение при закрытии вкладки

Полноценные черновики (персистентные, переживающие перезагрузку страницы) потребовали бы новой
таблицы и API — весомое расширение объёма работы. Сделан безопасный, полностью переиспользующий
уже существующую инфраструктуру вариант: `window.addEventListener('beforeunload', ...)`
предупреждает при попытке закрыть/перезагрузить вкладку, если открыта форма устройства или ИС с
несохранёнными изменениями — использует ту же `hasUnsavedChanges()`, что и предупреждение при
закрытии модального окна (сделанное в шаге 4). Проверяется дополнительно, что модальное окно
реально видно на экране — не мешает обычной навигации по разделам приложения.

## 1.4 (функционал). Импорт устройств из CSV

Добавлена кнопка «Импорт из CSV» (видна только в разделе «Физические устройства»). Реализовано
полностью автономным оверлеем поверх страницы — не через `#modal`, поэтому никак не пересекается
с состоянием обычных форм (`formOpenSnapshot`/`editingId`/`resource`). Создание записей идёт через
тот же самый, уже протестированный `/resources/devices POST`, что и обычная форма — новой логики
создания устройства не появилось.

Формат: колонки «Тип устройства, Производитель, Модель, Серийный номер, Системное имя, Здание,
Помещение, Стойка, Позиция» (порядок и регистр заголовков не важны). Обязательны только тип
устройства и серийный номер — остальные поля ищутся по названию в соответствующих справочниках;
ненайденные остаются пустыми, запись всё равно создаётся. По каждой строке — отдельный результат
(✅/❌ с понятной причиной), обработка не прерывается на первой ошибке.

Собственный минимальный CSV-парсер (без внешних библиотек) корректно обрабатывает поля в
кавычках с запятыми внутри, экранированные кавычки (`""`), CRLF-концы строк (типичный экспорт
из Excel) и пустые строки в файле.

## Инцидент в процессе работы и его исправление

При добавлении CSV-импорта неточный `str_replace` **случайно удалил сигнатуру функции
`closeModal`**, оставив только её тело — синтаксическая ошибка. Обнаружено немедленно повторной
проверкой `node --check` сразу после правки (не отложено на потом), строка восстановлена,
целостность всего окружающего кода проверена построчным просмотром и повторной проверкой на
дубли объявлений — синтаксис снова чист, всё на своих местах.
