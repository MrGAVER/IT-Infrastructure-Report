# РИС — Реестр ИТ-инфраструктуры 2.20.1

Приложение для учета информационных систем, физических устройств, сетевых подключений, виртуальных машин, контейнеров и программных активов с выгрузкой регламентированного Excel-отчета из 4 листов.

## Реализовано

### 1. Полный CRUD

Единый REST CRUD реализован для всех основных сущностей БД:

- организации;
- подразделения;
- здания, помещения, стойки;
- типы устройств, производители, модели;
- физические устройства;
- информационные системы;
- подразделения, IP и протоколы ИС;
- интерфейсы и IP интерфейсов;
- VLAN и привязки VLAN;
- физические подключения;
- среды виртуализации;
- виртуальные машины и их IP;
- контейнеры;
- программные активы;
- ПО физических устройств и VM;
- связи ИС с устройствами, VM и контейнерами;
- открытые порты;
- журнал аудита.

Для каждой сущности доступны:

```text
GET    /api/v1/resources/{resource}
GET    /api/v1/resources/{resource}/{id}
POST   /api/v1/resources/{resource}
PUT    /api/v1/resources/{resource}/{id}
DELETE /api/v1/resources/{resource}/{id}
GET    /api/v1/resources/{resource}/schema
```

Поддерживаются поиск `q`, `offset`, `limit`, проверка уникальности и обработка внешних ключей. Удаление объекта, на который есть ссылки, блокируется с HTTP 409.

### 2. Формы интерфейса

В браузерном интерфейсе добавлены динамические CRUD-формы. Форма строится по схеме конкретной таблицы и умеет:

- текстовые поля;
- числовые поля;
- большие текстовые поля;
- Boolean как Да/Нет;
- выпадающие списки для внешних ключей;
- создание;
- редактирование;
- удаление;
- поиск;
- просмотр списка.

Основные разделы вынесены в левое меню: ИС, устройства, интерфейсы, подключения, VM, контейнеры, ПО, VLAN, открытые порты и справочники.

### 3. Миграции Alembic

`Base.metadata.create_all()` больше не используется как механизм создания схемы.

Схема БД создается и обновляется миграциями:

```bash
cd backend
alembic upgrade head
```

Текущая миграция — удаление устаревшей реализации стеков устройств:

```text
backend/alembic/versions/b5e7c2d4a910_remove_device_stacks.py
```

Новая миграция после изменения моделей:

```bash
cd backend
alembic revision --autogenerate -m "описание изменения"
alembic upgrade head
```

Откат последней миграции:

```bash
alembic downgrade -1
```

В Docker миграция выполняется автоматически перед запуском Uvicorn.

### 4. Excel

`POST /api/v1/reports/inventory` создает XLSX с четырьмя листами:

1. `Перечень ИС`
2. `Инвентаризац. физ. устройств ИС`
3. `Организация подключений`
4. `Организация управления ВМ`

Генерация выполняется из нормализованной БД с объединением связанных объектов. Для листов включены перенос текста, фильтр, закрепление заголовка и автоматическая ширина колонок.

### 5. EXE для Windows

Приложение можно собрать в один `InfraRegistry.exe` с помощью PyInstaller.

EXE работает в локальном режиме на SQLite и не требует PostgreSQL или Docker.

При старте EXE:

1. создает `%LOCALAPPDATA%\InfraRegistry`;
2. выполняет Alembic migration `upgrade head`;
3. запускает локальный HTTP-сервер;
4. открывает браузер на `http://127.0.0.1:8000`.

Данные не находятся внутри EXE:

```text
%LOCALAPPDATA%\InfraRegistry\infra_registry.db
%LOCALAPPDATA%\InfraRegistry\reports\
```

Поэтому обновление EXE не удаляет реестр.

Сборка выполняется на Windows:

```bat
installer\build_windows.bat
```

Результат:

```text
dist\InfraRegistry.exe
```

Запуск:

```bat
InfraRegistry.exe
```

Параметры:

```bat
InfraRegistry.exe --port 8010
InfraRegistry.exe --no-browser
```

Подробная инструкция: `README_EXE.md`.

## Запуск через Docker

```bash
docker compose up --build
```

Открыть:

```text
http://localhost:8000
http://localhost:8000/docs
```

## Локальный запуск без Docker

Python 3.12+:

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux/macOS
source .venv/bin/activate

pip install -r backend/requirements.txt
cd backend
alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## Архитектура

```text
Browser / EXE
     |
     v
FastAPI + Uvicorn
     |
     +-- SQLAlchemy ORM
     |      |
     |      +-- SQLite (EXE / локально)
     |      +-- PostgreSQL 16 (Docker / сервер)
     |
     +-- Alembic migrations
     |
     +-- openpyxl -> XLSX
```

## Важное замечание по EXE

EXE-вариант рассчитан на локальную работу одного пользователя. Для общего сетевого доступа нескольких сотрудников следует использовать серверный вариант с PostgreSQL.


## EXE 2.1: исправление 404 на `/`

Для Windows пересоберите EXE командой `installer\build_windows.bat`. Версия 2.1 явно передает путь к `frontend` из launcher и отдает `frontend/index.html` по `/`. После успешного запуска `GET /` должен возвращать `200 OK`.


## Изменения версии 2.2

- В форме добавления физического устройства (`Физические устройства`) рядом с полями **Тип устройства, Производитель, Модель, Здание, Помещение, Стойка** появилась кнопка `＋`. Она позволяет создать запись непосредственно из формы устройства, не переходя в раздел справочников.
- Для моделей можно сразу выбрать производителя; для помещений — здание; для стоек — помещение.
- Поле `№` информационной системы больше не показывается в форме и не принимается как пользовательское значение API. Нумерация в Excel формируется автоматически по порядку строк при каждом экспорте.
- Аналогично колонка `№` в листах 2 и 3 всегда генерируется экспортом (`1..N`) и не является полем ввода.


## Версия 2.5
Модель физического устройства теперь однозначно связана с производителем и типом устройства. Например, Huawei 2288 не может быть выбран как модель коммутатора. В форме физического устройства модели фильтруются по обеим выбранным характеристикам.


## Версия 2.8

- В форме физического устройства ОС отображается как «Наименование + версия».
- В списках и связях внешние ключи отображаются человекочитаемыми значениями вместо UUID.
- Поле «Порт управления» вынесено из отдельного поля физического устройства в объединенный редактор интерфейсов.
- В форме физического устройства можно сгенерировать интерфейсы по количеству физических портов, используя шаблоны имени и номера (`{n}`, `{n0}`), а затем вручную изменить любые поля или добавить отдельные интерфейсы.
- Для интерфейса добавлен признак «Управление». Он используется для определения порта управления и при формировании Excel.
- Добавлен атомарный API `PUT /api/v1/devices/{device_id}/interfaces` для синхронизации интерфейсов.
