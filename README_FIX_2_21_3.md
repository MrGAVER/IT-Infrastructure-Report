# Infra Registry 2.21.3 — «Размещение» и «VLAN устройства»

## 1. Колонка «Позиция» выходила за пределы видимой области

`.location-grid` задавала колонки как `1.2fr 1.2fr 1.2fr .8fr` без `minmax(0, ...)`. По умолчанию
CSS Grid считает минимальный размер трека по минимальному контенту (`min-content`) вложенных
элементов, а не по `fr`-доле. Так как `<select>` внутри блока «Здание/Помещение/Стойка» может
содержать длинные названия, их «естественная» ширина оказывалась больше, чем доступное место —
и последняя, самая узкая колонка («Позиция») выталкивалась за пределы диалогового окна
(`overflow:auto` у `.dialog` добавлял горизонтальную прокрутку вместо переноса).

**Исправление** (`frontend/static/app.css`):
- колонки `.location-grid` теперь `minmax(0,1.2fr) minmax(0,1.2fr) minmax(0,1.2fr) minmax(0,.8fr)`;
- всем элементам внутри `.location-grid` явно разрешено сжиматься (`min-width:0`);
- `<select>` растягивается на всю ширину своей колонки, а не по контенту.

Колонка «Позиция» теперь всегда видна и не требует горизонтальной прокрутки.

## 2. Блок «VLAN устройства»: невозможно было создать/сохранить новый VLAN

**Причина.** Кнопка «Новый VLAN для устройства» добавляла в форму «сырую» встроенную строку
(4 текстовых поля + выбор домена) без собственной кнопки сохранения — запись реально создавалась
только при отправке формы устройства целиком, вместе со всеми остальными полями устройства.
Это не соответствовало ни одному другому сценарию быстрого добавления в приложении (у справочников,
подключений, интерфейсов, ИС, самого VLAN — у всех есть отдельная форма/модалка с явной кнопкой
«Сохранить»/«Добавить»). А главное — созданный таким образом VLAN не был известен интерфейсному
редактору «VLAN на порту» (тот список строится по отдельному, более старому справочнику
«VLAN, разрешенные для типа устройства», а не по фактически назначенным устройству VLAN),
поэтому только что добавленный VLAN не появлялся как опция для портов, даже после сохранения.

**Исправление** (`frontend/static/app.js`):
- кнопка «Новый VLAN для устройства» теперь открывает ту же модалку быстрого добавления, что и
  весь остальной интерфейс (`openQuickModal('vlans', ...)`) — три поля: VLAN ID, VLAN Name,
  Описание, с собственной кнопкой «Добавить». VLAN создается в БД сразу по нажатию, а не
  откладывается до сохранения формы устройства — так что несохранённые обязательные поля в
  остальной части формы устройства больше не блокируют создание VLAN;
- созданный VLAN сразу добавляется в список «VLAN устройства» и сразу же становится доступен
  для выбора в чекбоксах «VLAN на порту» соответствующего интерфейса — без обновления страницы
  и без предварительного сохранения устройства;
- убран более неиспользуемый код инлайн-создания VLAN (`addLocalDeviceVlan`, ветка `_new` в
  рендере строки и в `saveDeviceVlans`).

## Проверка

- `node --check frontend/static/app.js` — синтаксис корректен.
- Проверены точки входа: кнопка «Новый VLAN для устройства» → `openQuickModal('vlans','device-vlan-new')`
  → `saveQuickForm` → добавление в `deviceVlanRows` и `deviceVlanOptions` → перерисовка списка
  VLAN устройства и редактора интерфейсов.
