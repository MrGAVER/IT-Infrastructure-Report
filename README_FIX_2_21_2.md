# Infra Registry 2.21.2 — исправления интерфейса физических устройств и VLAN

## 1. Блок «Размещение» в форме физического устройства

Поля Здание / Помещение / Стойка / Позиция в стойке были без подписей — вместо подписи использовался
только текст плейсхолдера внутри выпадающего списка ("— здание —" и т.п.), а сама подпись поля
отсутствовала. Теперь каждое поле обернуто как обычное `label.field` с явной подписью
(«Здание», «Помещение», «Стойка», «Позиция в стойке») — по тому же визуальному шаблону, что и
остальные поля формы.

## 2. Создание VLAN

**Причина проблемы.** Кнопка «+ VLAN» на дашборде VLAN вызывала общий `openForm()`, который строит
форму по `schema` — объекту схемы текущего REST-ресурса. Но при открытии раздела VLAN (`openResource('vlans')`)
загрузка `schema` для VLAN не выполнялась (функция сразу уходила в отдельный дашборд VLAN и завершалась
до строки, где `schema` обновляется). В результате:

- если раздел VLAN открывали первым — `schema` оставалась `null`, и `openForm()` падал с ошибкой
  на первой же строке, где обращается к `schema.name`; модалка вообще не открывалась;
- если до этого была открыта другая таблица (например, «Физические устройства») — `schema` оставалась
  от неё, и форма VLAN показывала поля физического устройства вместо VLAN ID / VLAN Name / Описание,
  а сохранение уходило по адресу `/resources/vlans` с посторонними данными.

И даже при исправлении одной лишь загрузки схемы, стандартная форма показала бы лишнее поле
«Домен VLAN» — управление доменами сделано отдельно (кнопки «Создать домен VLAN» / «Домены VLAN»),
и на этапе быстрого создания VLAN оно не нужно.

**Исправление.** Добавлена отдельная форма для VLAN (как уже сделано для типов устройств, подключений,
интерфейсов и ИС): `openVlanForm()` / `saveVlanForm()` — только VLAN ID, VLAN Name и Описание, кнопка
«Сохранить» из общей модалки теперь действительно сохраняет запись. `openForm()`, `saveForm()` и
`removeItem()` соответствующим образом ветвятся на VLAN. В таблицу дашборда VLAN добавлен недостающий
столбец «Действия» (Изменить / Удалить) — раньше отдельные определения VLAN нельзя было редактировать
или удалять из этого экрана вообще.

## 3. Форма «Открытые порты»

При ручном разборе форм на предмет несоответствий обнаружено: `owner_type` и `owner_id` (владелец
открытого порта — устройство или VM) не являются внешним ключом на уровне БД (полиморфная связь),
поэтому общий генератор полей выводил их как обычные текстовые поля — пользователю нужно было вручную
печатать `physical_device`/`virtual_machine` и вставлять UUID владельца, в отличие от всех остальных
похожих связей в приложении, которые показываются выпадающими списками с человекочитаемыми именами.

Также поля `port` и `protocol` были полностью скрыты из формы без замены, хотя `port` — обязательное
поле в БД: создать запись открытого порта было невозможно в принципе (запрос не проходил бы валидацию).

**Исправление:**
- `owner_type` — теперь выпадающий список («Физическое устройство» / «Виртуальная машина»);
- `owner_id` — выпадающий список конкретных устройств/VM, обновляется при смене типа владельца;
- `port` и `protocol` — возвращены в форму как обычные поля (порт обязателен), с автозаполнением
  при выборе записи из справочника протоколов/портов, но остаются редактируемыми вручную.
