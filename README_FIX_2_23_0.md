# Infra Registry 2.23.0

## 1. Модель/тип устройства — ошибка сохранялась даже после прошлого фикса

Прошлый фикс (`onDeviceModelChanged`) решал только один из двух путей рассинхронизации.
Оставшийся: скрытые поля «Производитель»/«Тип устройства» при ОТКРЫТИИ формы устройства
брались из **собственных** сохранённых значений устройства, а не из выбранной модели. Если тип
модели поменяли прямо в каталоге «Производитель → Тип → Модель» (а не в форме устройства),
привязанное устройство при следующем открытии сразу оказывалось в рассогласованном состоянии —
без единого клика по полю модели — и сохранение падало с той же ошибкой. Теперь при открытии
формы, если модель выбрана, тип/производитель берутся из **неё** — форма самовосстанавливается.

## 2. Физические устройства

**VLAN устройства пропадали после «Отмена».** Добавление VLAN через «+ VLAN» создавало запись
в справочнике сразу (это верно), но связь с устройством раньше жила только в памяти формы до
нажатия «Сохранить». Теперь для уже существующего устройства связь тоже создаётся сразу; удаление
симметрично — удаляется немедленно, а не только на следующем сохранении.

**«VLAN на порту» теперь отсортированы по VLAN ID** — и в карточках интерфейсов, и в панели
массового редактирования.

## 3. Информационные системы

**Список ВМ в источнике не пропадает, если сервер не выбран.** Не нашёл воспроизводимой причины
через статический анализ и симуляцию — код фильтрации технически работал верно в тестах. На всякий
случай сделал список принципиально не фильтруемым до пустоты: теперь показываются все ВМ всегда
(с сортировкой «сначала с выбранного сервера» как удобство, не как фильтр).

**«Описание СКЗИ» стало справочником** (`CryptoProtectionMeans`, миграция `e7a2c9f4d813`, с
переносом старых текстовых значений и быстрым добавлением из формы).

## 4. Виртуальные машины

**Поле «IP администрирования» убрано** — столбец `administration_ip` удалён из модели (данные
перенесены в `vm_ips` при миграции, если были). Источник истины теперь — блок «IP-адреса
виртуальной машины».

**В блоке IP-адресов ВМ — переключатель «IP администрирования».** Флажок-чекбокс заменён на
радио-кнопку (одна группа на всю ВМ) — гарантированно только один IP может быть отмечен как
административный, именно он используется в отчете.

## 5. Отчет Excel

**Работники/подразделения (Лист 1).** Не нашёл воспроизводимого дефекта в коде сохранения/чтения
(прямая симуляция с реальными данными ISDepartment показала корректную работу). Добавил
подстраховку — выбор подразделения теперь синхронизируется в состояние формы сразу по изменению
поля, а не только перед сохранением.

**IP-адрес ИС (Лист 1) — физический сервер туда больше не попадает.** Раньше и явный источник
типа «физический сервер», и авто-заполнение при его выборе подставляли IP всех интерфейсов сервера
в поле взаимодействия ИС. Убрано и на бэкенде (`_source_ip_values`), и во фронтенде
(`onISSourceDeviceChanged`) — оборудование по-прежнему попадает в столбец «Оборудование», а не в
столбец IP.

**Порт управления (Лист 2) теперь показывает VLAN**, если управление организовано через VLAN, а
не через физический интерфейс — аналогично уже сделанному для дашборда.

**Лист «Организация подключений» — полностью переработан:**
- теперь показаны **все порты**, а не только те, что участвуют в подключениях;
- порты без подключения на одном устройстве, у которых совпадает IP (в т.ч. отсутствие IP),
  группируются в одну строку — как и требовалось;
- VLAN ID/Name по-прежнему берутся с соседнего порта, если на своём не указаны (сохранено с
  прошлого раза);
- «IP-адрес порта соседнего устройства» теперь берёт **IP-адреса управления** соседнего
  устройства (включая VLAN-based), а не только IP конкретного физического порта — это же
  относится и к самим этим адресам «не назначен», которые раньше маскировали реальный
  management-IP соседа.
