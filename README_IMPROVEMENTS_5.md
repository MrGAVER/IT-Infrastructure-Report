# Infra Registry — реализация предложений по улучшению (шаг 5)

## 4.5 + 4.2 (оптимизация). Кеширование схем ресурсов и статичных справочников

Добавлен кеш в памяти на время сессии в `get()` (`app.js`) — единой точке, через которую проходят
все обращения к API:
- **Схемы ресурсов** (`/resources/<x>/schema`) кешируются всегда — они меняются только миграциями
  БД, никогда в рантайме.
- **Статичные справочники** (типы устройств, производители, модели каталога, типы/скорости
  интерфейсов, категории и версии ОС, организации/способы техподдержки, СКЗИ, оборудование
  размещения ИС, справочник протоколов, здания/помещения/стойки/подразделения) кешируются только
  при точном запросе «весь список» (`?limit=1000` без дополнительных фильтров).

Намеренно **не кешируются** первичные данные — устройства, ВМ, контейнеры, подключения,
интерфейсы, IP-адреса, назначения VLAN — они меняются в ходе обычной работы слишком часто, риск
показать устаревшие данные не стоит экономии одного запроса.

Кеш **автоматически инвалидируется**: любой непустой (не-GET) запрос к ресурсу сбрасывает
кеш-запись его списка — так что запись, добавленная через модалку быстрого добавления
(например, новый тип устройства), сразу видна в следующей форме без устаревших данных.

Проверено отдельной эмуляцией в Node.js (без браузера): для каждого класса URL (схема,
кешируемый справочник, первичные данные, отфильтрованный запрос, запрос с `offset`) подтверждено
корректное решение "кешировать/не кешировать", а также корректное определение ресурса для
инвалидации из URL мутирующего запроса.

## 2.1 (интерфейс). Распараллелены независимые запросы при открытии форм

Форма «Информационная система» делала **12 последовательных** `await`-запросов при открытии —
большинство из них (10 справочников) не зависят друг от друга. Переписано на `Promise.all`:
все независимые запросы уходят одним параллельным раундом, локальная фильтрация (список серверов
по типу устройства) выполняется уже после того, как все данные получены.

Форма «Физическое устройство» аналогично делала последовательно `loadInterfaceEditor` (порты) и
`loadDeviceVlanEditor` (VLAN устройства) — эти два редактора пишут в разные контейнеры формы и не
читают состояние друг друга при первой загрузке (проверено построчным разбором обеих функций),
поэтому безопасно объединены в `Promise.all`. То же сделано в двух местах, где эта пара
перезагружается при смене модели оборудования в форме (`onDeviceModelChanged`,
`onDeviceCatalogChanged`).
