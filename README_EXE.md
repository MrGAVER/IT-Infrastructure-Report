# Запуск как EXE в Windows

## Что делает EXE

`InfraRegistry.exe` — самостоятельное Windows-приложение с локальным веб-интерфейсом. При запуске:

1. создаёт каталог `%LOCALAPPDATA%\InfraRegistry`;
2. создаёт/обновляет SQLite БД `infra_registry.db`;
3. автоматически выполняет `Alembic upgrade head`;
4. запускает локальный FastAPI/Uvicorn сервер;
5. открывает браузер на `http://127.0.0.1:8000`.

Интернет и PostgreSQL для EXE-режима не требуются.

## Где хранятся данные

- База: `%LOCALAPPDATA%\InfraRegistry\infra_registry.db`
- Excel: `%LOCALAPPDATA%\InfraRegistry\reports\`
- Логи: выводятся в окно EXE/консоли.

Поэтому обновление самого EXE не удаляет пользовательскую БД.

## Сборка EXE

Сборка выполняется **на Windows**, потому что PyInstaller формирует исполняемый файл под текущую ОС.

На ПК разработчика:

```bat
installer\build_windows.bat
```

Результат:

```text
dist\InfraRegistry.exe
```

## Запуск

Двойной щелчок по `InfraRegistry.exe`.

Либо:

```bat
InfraRegistry.exe --port 8010
```

Без автоматического открытия браузера:

```bat
InfraRegistry.exe --no-browser
```

## Перенос на другой ПК

Достаточно скопировать `InfraRegistry.exe`. При первом запуске приложение самостоятельно создаст БД и каталоги.

## Важное ограничение

EXE-вариант предназначен для **однопользовательского/локального режима**. Для общей работы нескольких сотрудников по сети рекомендуется Docker + PostgreSQL или отдельная серверная установка.


## Исправление EXE 2.1

В версии 2.1 исправлена ошибка, при которой после сборки PyInstaller запрос `GET /` возвращал `404 Not Found`.

Причина была в том, что путь к frontend определялся косвенно через расположение `main.py` внутри PyInstaller `_MEIPASS`. В EXE теперь путь к интерфейсу передается launcher-ом явно через `INFRA_REGISTRY_FRONTEND_DIR`, а endpoint `/` напрямую возвращает `frontend/index.html`.

После запуска в консоли должен появиться запрос:

```text
GET / HTTP/1.1 200 OK
```

Если используется старый EXE, его необходимо пересобрать новым `infra_registry.spec`. Старый EXE заменять можно, база данных `%LOCALAPPDATA%\InfraRegistry\infra_registry.db` не удаляется.


## Хранение базы данных

В EXE-режиме файл базы данных SQLite хранится **рядом с исполняемым файлом**:

```text
InfraRegistry.exe
infra_registry.db
reports\
```

Путь определяется как каталог `InfraRegistry.exe`, а не `%LOCALAPPDATA%`. Это позволяет переносить каталог приложения целиком вместе с базой. При запуске выполняется `Alembic upgrade head`.

Важно: каталог с EXE должен быть доступен для записи текущему пользователю, поскольку приложение создает/изменяет `infra_registry.db`, каталог `reports` и выполняет миграции.


## Версия 2.5
Модель физического устройства теперь однозначно связана с производителем и типом устройства. Например, Huawei 2288 не может быть выбран как модель коммутатора. В форме физического устройства модели фильтруются по обеим выбранным характеристикам.


## Версия 2.11

- В форме физического устройства ОС отображается как «Наименование + версия».
- В списках и связях внешние ключи отображаются человекочитаемыми значениями вместо UUID.
- Поле «Порт управления» вынесено из отдельного поля физического устройства в объединенный редактор интерфейсов.
- В форме физического устройства можно сгенерировать интерфейсы по количеству физических портов, используя шаблоны имени и номера (`{n}`, `{n0}`), а затем вручную изменить любые поля или добавить отдельные интерфейсы.
- Для интерфейса добавлен признак «Управление». Он используется для определения порта управления и при формировании Excel.
- Добавлен атомарный API `PUT /api/v1/devices/{device_id}/interfaces` для синхронизации интерфейсов.

## Версия 2.16

- Добавлен единый справочник «Протокол / порт» с номером порта, типом протокола и описанием. Он используется в протоколах ИС и открытых портах.
- В форме ИС объединены IP, физические устройства, ВМ и контейнеры в единый блок «Размещение, IP-адреса и источники данных ИС».
- Для источников из базы IP подставляются автоматически; при выборе ВМ можно дополнительно выбрать физический сервер, после чего список ВМ фильтруется по этому серверу.
- Добавлено быстрое создание подразделения непосредственно из формы ИС.
- Новая организация технической поддержки сразу появляется в текущем поле выбора без перезагрузки страницы.
- В форме ВМ не отображаются поля «Гипервизор» и «Состояние устройства».
