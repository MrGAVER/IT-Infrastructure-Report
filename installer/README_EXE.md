# РИС — Реестр ИТ-инфраструктуры (InfraRegistry.exe)

Самостоятельное Windows-приложение с локальным веб-интерфейсом. Интернет, PostgreSQL и Docker не нужны.
Полное описание — в `README.md` репозитория (разделы «Запуск как EXE» и «Файл настроек…»).

## Запуск

Двойной щелчок по `InfraRegistry.exe` (или `run_infra_registry.bat`). Приложение создаёт или обновляет базу,
запускает сервер и открывает браузер на `http://127.0.0.1:8000`. Параметры командной строки важнее файла настроек:

```bat
InfraRegistry.exe --port 8010
InfraRegistry.exe --no-browser
```

Каталог с EXE должен быть доступен для записи текущему пользователю.

## Где хранятся данные

Данные лежат **рядом с `InfraRegistry.exe`**, а не внутри него и не в профиле пользователя:

```text
InfraRegistry.exe
infra_registry.toml     файл настроек (создаётся при первом запуске)
infra_registry.db       база данных SQLite
reports\                сформированные отчёты
```

Другой каталог данных задаёт переменная окружения `INFRA_REGISTRY_DATA_DIR`. Для переноса на другой компьютер
скопируйте каталог целиком (или только EXE — база и файл настроек будут созданы заново).

## Обновление и резервные копии

Обновление — замена `InfraRegistry.exe` на новую версию: накопленный реестр остаётся в `infra_registry.db`.
Если версия схемы базы старше, при запуске **перед миграцией** рядом с базой создаётся копия
`infra_registry.pre-<версия>.<дата-время>.bak`; хранятся 5 последних, путь выводится в консоли. Если копию создать
не удалось, миграция не выполняется, и база остаётся нетронутой.

Чтобы вернуться после неудачного обновления: закройте приложение, верните прежний EXE, переименуйте
`infra_registry.db` (например, в `infra_registry.broken.db`) и скопируйте нужный `.bak` под именем `infra_registry.db`.

**Плановые копии.** Пока приложение запущено, оно само делает копии базы: при запуске, если плановых копий ещё нет или
последняя старше суток, и затем раз в сутки работы (EXE выключают на ночь, поэтому проверка идёт при каждом запуске). Копия
согласованная, проверяется на целостность, лежит в папке `backups` рядом с базой под именем
`infra_registry.auto.<дата-время>.bak`; хранятся 7 последних. Неизменённую с прошлой копии базу не копируют. **Копия на том же
диске, что и база, не защитит от поломки этого диска** — задайте папку на другом диске или сетевую (параметр `directory` в
разделе `[backup]` файла `infra_registry.toml`). Восстановление — как после неудачного обновления (см. выше).
Копию на другой носитель и файл `infra_registry.toml` всё равно стоит время от времени сохранять сами.

## Настройки и доступ с других компьютеров

Файл `infra_registry.toml` лежит рядом с EXE; изменения применяются после перезапуска.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `[server] port` | `8000` | порт веб-интерфейса (`--port` важнее) |
| `[server] open_browser` | `true` | открывать браузер при запуске (`--no-browser` важнее) |
| `[access] allowed_clients` | `[]` | IP-адреса и подсети компьютеров, которым разрешено подключаться по сети |
| `[access] allowed_hosts` | `[]` | имена компьютера, по которым открывают приложение (по IP-адресу — без настройки) |
| `[backup] interval_hours` | не задан (24) | как часто делать плановую копию базы, часов; `0` — не делать; допустимы дробные значения |
| `[backup] keep` | не задан (7) | сколько плановых копий хранить (не меньше 1) |
| `[backup] directory` | не задан (`backups` рядом с базой) | полный путь к папке копий, лучше на другом диске, например `'D:\RIS-backups'` |

По умолчанию доступ **только с этого компьютера**. Чтобы пускать другие компьютеры, перечислите их в
`allowed_clients` (`["192.168.1.15"]` или подсеть `["192.168.1.0/24"]`) и перезапустите приложение. Затем:

1. Разрешите входящие TCP-подключения на порт приложения в брандмауэре Windows (командная строка администратора):
   `netsh advfirewall firewall add rule name="RIS" dir=in action=allow protocol=TCP localport=8000`.
2. С другого компьютера откройте `http://<IP-адрес компьютера с EXE>:8000`.
3. Сначала включите аутентификацию («Настройки → Аутентификация»), потом открывайте доступ: пока вход выключен,
   любой разрешённый компьютер читает и меняет весь реестр без пароля.

Подключение идёт по HTTP без шифрования — используйте только доверенную сеть. SQLite рассчитана на небольшое число
одновременных пользователей; для многих сотрудников используйте серверный вариант (Docker + PostgreSQL).
