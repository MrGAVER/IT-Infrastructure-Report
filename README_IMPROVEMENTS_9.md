# Infra Registry — реализация предложений по улучшению (шаг 9)

## 1.1 (функционал). Журнал аудита теперь доступен в интерфейсе

Таблица `audit_log` уже собиралась при каждом создании/изменении/удалении записи (`crud.py:audit()`),
но нигде не отображалась пользователю — данные копились, но были недоступны без прямого обращения
к API. Добавлен раздел «Аудит»: кнопка на дашборде (не как числовая карточка — для журнала нет
осмысленного "счётчика", это просто переход к разделу) открывает таблицу последних 300 действий,
отсортированную от новых к старым, с колонками: дата/время, раздел, запись, действие, подробности.

Раздел строго read-only — не показывает кнопки «Добавить»/«Изменить»/«Удалить» (в отличие от
обычных разделов), поскольку журнал аудита в принципе не должен редактироваться из интерфейса.
Реализовано отдельным маршрутом в `openResource()` (по аналогии с уже существующим особым случаем
для VLAN-дашборда), а не через общий `renderList()`.

**Человекочитаемые подписи записей** резолвятся пакетно — один запрос на тип сущности (устройства,
типы устройств и т.д.), а не один запрос на каждую строку журнала, что при 300 записях сохраняет
разумное число обращений к API даже без специальной оптимизации сервера.

**Найденный по пути нюанс:** для записей синхронизации интерфейсов (`SYNC`) в БД `entity_type`
исторически записывается как `'interfaces'`, хотя `entity_id` на самом деле — идентификатор
**устройства**, а не интерфейса (так сделано в `crud.py:sync_interfaces`, не тронуто). Без поправки
такие записи в новом журнале ошибочно показывали бы «запись удалена», хотя устройство на месте.
Добавлено разрешение по эффективному типу: для `SYNC`-записей раздела `interfaces` подпись
резолвится по `devices`. Логика группировки проверена отдельной эмуляцией в Node.js.

- `node --check app.js` — чисто, дублирующихся объявлений функций нет.
- В процессе редактирования была допущена и сразу исправлена собственная ошибка: неточный
  `str_replace` временно затёр функцию `openResource` при добавлении журнала аудита — обнаружено
  немедленно повторной проверкой (`grep` не находил объявление функции), восстановлено, проверено
  синтаксисом и отсутствием дублей.
- Отдельная эмуляция в Node.js: группировка записей по типу сущности с учётом SYNC-исключения
  (запись синхронизации интерфейсов корректно попадает в группу устройств, а не интерфейсов).
- Полный тестовый набор backend (эта часть работы фронтенд-only): 25 тестов, 23 пройдено,
  2 корректно пропущено.
